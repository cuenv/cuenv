# cuenv 0.61.0

## Infrastructure: data sources and sensitive references

Read-only provider lookups can be declared in `infrastructure.data`, next to
`resources`. `cuenv infrastructure provider add` now also generates a
`#DataSource` package for each of the provider's data sources. A resource
argument can refer to a lookup's output, either with a native selector or with
a `fromDataSource` descriptor. Data sources are read during plan, or during
apply when what they depend on is still changing, and they are never written to
state.

Output references can now come from sensitive attributes, such as a generated
API token copied into a secret manager. The receiving argument shows as
`(sensitive)` in plans, the value is registered for redaction, and state records
which attributes are sensitive, so later runs keep them masked during destroy
and orphan plans.

Upgrading:

- The state database migrates from version 1 to version 2 the first time a new
  cuenv uses it. The migration runs in one transaction. Once it has run, older
  cuenv versions refuse that database.
- A provider that has data sources needs its pin refreshed. Run
  `cuenv infrastructure provider add <source>@<same version>`. `cuenv sync`
  refuses to change a schema digest pin without being told. Pins for providers
  without data sources are unchanged.
- References still take top-level scalar values only. Selecting items from
  collections, such as Cloudflare permission group lookups, is tracked in
  [#545](https://github.com/cuenv/cuenv/issues/545).

See [PR #544](https://github.com/cuenv/cuenv/pull/544) and
[Infrastructure](../src/content/docs/how-to/infrastructure.md).

## Infisical: GitHub OIDC

CI jobs can authenticate to Infisical with GitHub OIDC, so no Infisical secret
needs to be stored in CI. There are two ways to set it up:

- `#InfisicalOidc` adds a step that fetches the Actions ID token into
  `INFISICAL_AUTH_JWT` and grants `id-token: write`. cuenv then logs in with
  `INFISICAL_MACHINE_IDENTITY_ID` and resolves `#InfisicalSecret` references
  itself, so its policies and redaction still apply. The login happens before
  the first task, while the ID token is still valid. The identity's
  access-token TTL must cover the whole run.
- `#InfisicalSecretsAction` runs `Infisical/secrets-action` with OIDC. The
  action exports the secrets as job environment variables, and tasks read them
  with `#EnvPassthrough`.

The existing `#Infisical` contributor is unchanged.

Upgrading: the resolver now refuses a partial or ambiguous login. That includes
having `INFISICAL_MACHINE_IDENTITY_ID` set for another tool while using
Universal Auth or `INFISICAL_TOKEN`. Unset it for cuenv, or complete the OIDC
configuration. See [PR #546](https://github.com/cuenv/cuenv/pull/546) and
[Secrets](../src/content/docs/how-to/secrets.md).

## Other changes

- `cuenv fmt` fails when a formatter fails, and runs formatters with the
  project environment ([#535](https://github.com/cuenv/cuenv/pull/535)).
- The schema validates the same way on CUE v0.15 through v0.18
  ([#518](https://github.com/cuenv/cuenv/pull/518)).
- Generated GitHub workflows use `actions/checkout@v7`
  ([#534](https://github.com/cuenv/cuenv/pull/534)).
- Dependency updates: gix 0.85, sha2 0.11, hmac 0.13, toml_edit 0.25, lru 0.19
  and similar 3.2.
