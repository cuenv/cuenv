# cuenv 0.59.0

## Infrastructure: Cloudflare D1 as a state backend

`infrastructure.state` now takes exactly one of `turso` or `d1`. A D1
database is reached through the Cloudflare REST API, so no Worker is needed:

```cue
infrastructure: state: d1: {
	accountId:  "0123456789abcdef0123456789abcdef"
	databaseId: "0b2c3d4e-5f60-4718-8293-a4b5c6d7e8f9"
	token:      schema.#OnePasswordRef & {ref: "op://platform/d1/token"}
}
```

Both backends share one SQLite implementation, so locking, compare and swap,
ownership, migrations and recovery behave identically. The D1 transport binds
text parameters only, sends parameters only in single-statement requests and
honours `Retry-After`. Its error messages never name the account or database.
See [PR #523](https://github.com/cuenv/cuenv/pull/523) and
[Infrastructure](../src/content/docs/how-to/infrastructure.md#configure-the-state-database).

## Breaking: the state token is configured in CUE

Each state backend now takes one `token`, written like a project environment
variable: a string, a `#Secret`, an interpolation, or
`#EnvPassthrough & {name: "…"}`. One database serves the top level and every
environment, so there is one token. The token is redacted from all output and
never reaches a provider; a passthrough variable is withheld from providers.

`authenticationTokenEnvironmentVariable` is removed, and `TURSO_AUTH_TOKEN` is
no longer read implicitly. To keep reading the token from the environment,
name the variable explicitly:

```cue
infrastructure: state: turso: {
	url:   "libsql://platform-acme.turso.io"
	token: schema.#EnvPassthrough & {name: "TURSO_AUTH_TOKEN"}
}
```

State-only commands (`state list`, `state remove`, `state recover`,
`state adopt`, `unlock`) no longer resolve any project `env` variables.

## Fix: struct-literal passthrough in task `env`

A task `env` value written as `{cuenvPassthrough: true, name: "X"}` also
matched the open `#Secret` definition and failed to evaluate as an incomplete
value. `#Secret` now forbids `cuenvPassthrough`, as it already forbade `value`
and `policies`.
