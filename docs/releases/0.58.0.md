# cuenv 0.58.0

## Infrastructure: import existing resources and reference outputs

`cuenv infrastructure import <address> <identifier>` brings an existing
provider resource under management. It imports the resource into state,
refreshes it, and prints the plan command to run next. It does not apply any
infrastructure changes.

Resources can now use another resource's outputs in their configuration.
Write a native CUE selector such as
`infrastructure.resources.primary.outputs.id`. CUE evaluates the selector, and
the infrastructure runtime retains its reference provenance and infers the
dependency between the two resources.

When a referenced output is unknown, a provider-required replacement stays in
the confirmed plan. Replacements of the producing and consuming resources are
ordered safely within one apply.

See [PR #519](https://github.com/cuenv/cuenv/pull/519) and
[Infrastructure](../src/content/docs/how-to/infrastructure.mdx).

## Nix: a default package that runs on NixOS

On Linux, `packages.cuenv` is a portable glibc 2.17 binary that loads
`/lib64/ld-linux-*.so.2`, so it fails on NixOS. Releases still ship that
portable binary to other distributions. The flake now also provides
`cuenv-nix`, which uses the Nix glibc loader, and `packages.default` and
`apps.default` point to it. See
[Install](../src/content/docs/how-to/install.mdx).

The current flake has since made `packages.cuenv` Nix-native and removed the
`cuenv-nix` alias. Portable release binaries are built separately.
