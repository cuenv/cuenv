# cuenv 0.77.0

## Bazel remote caching, strict OS sandboxing, and cache diagnostics

cuenv now supports shared Bazel-compatible remote caches over both gRPC REAPI v2 (`grpc://`, `grpcs://`) and HTTP/REST (`http://`, `https://`), paired with OS-enforced strict sandboxing and local cache tooling ([#638](https://github.com/cuenv/cuenv/pull/638), [#644](https://github.com/cuenv/cuenv/pull/644)):

- **Remote cache backends & auth**: Configure `cache.remote` with bearer tokens, custom headers, or Bazel-compatible credential helpers (`auth.credentialHelper`, such as Namespace's `bazel-credential-nsc`) with RFC 3339 `expires`-aware caching and automatic refresh.
- **Ambient CI auth mode**: Set `cache.remote.ci.authMode: "ambient"` to consume `$GITHUB_ENV`-provisioned cache configuration without injecting static secrets or conflicting with existing job `environment` declarations, while keeping `CUENV_REMOTE_CACHE_UPLOAD` gated to protected triggers and supporting `isolatedCacheDir`.
- **Custom CA bundles & mTLS**: Configure `cache.remote.tls` (`caCertPath`, `clientCertPath`, `clientKeyPath`, or `CUENV_REMOTE_CACHE_*` environment overrides) on both gRPC and HTTP endpoints.
- **Resilience & throughput**: Automatic exponential-backoff retries with a shared circuit breaker across gRPC and HTTP CAS/ActionCache RPCs, plus asynchronous background remote uploads during task-graph execution (`cuenv task`) with bounded flushing on exit.
- **Strict sandboxing & Nix closure runtimes**: Linux unprivileged user/mount/PID/network namespaces now support pinned Nix runtime closures (`Runtime::NixClosure`) verified from `nix-store --query --requisites` without needing a pre-mounted SquashFS/EROFS image. macOS probes Seatbelt availability cleanly when running inside nested sandboxes.
- **Cache CLI**: Added `cuenv cache status`, `stats`, `verify`, `gc`, `prune`, `inspect <digest>`, and `diff <left> <right>` for cache maintenance and action-key miss analysis.

## Local affected tasks and CI task sharding

- **`cuenv task --affected` / `--from <REF>`**: Filter local task runs (bare `--affected`, `--label`, named tasks, and `--dry-run`) using the same `gix`-based changed-file and fail-closed affected-task engine as `cuenv ci` ([#644](https://github.com/cuenv/cuenv/pull/644)).
- **`cuenv ci --shard <INDEX>/<TOTAL>`**: Deterministically partition affected CI tasks in round-robin order across `1..=total` shards ([#644](https://github.com/cuenv/cuenv/pull/644)).

## Toolchain & schema upgrades

- **CUE v0.18**: Upgraded the Go CUE bridge and schema modules to CUE v0.18 (`v0.18.0`) ([#639](https://github.com/cuenv/cuenv/pull/639)).
- **Rust 1.100.0**: Raised the workspace Rust toolchain and MSRV to 1.100.0 ([#628](https://github.com/cuenv/cuenv/pull/628)) and cleaned up stale `deny.toml` advisory ignores ([#641](https://github.com/cuenv/cuenv/pull/641)).
