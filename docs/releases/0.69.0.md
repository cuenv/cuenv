# cuenv 0.69.0

## Infrastructure: write-only resource arguments

A managed string argument can now compose `schema.#WriteOnly` with a secret on the same value field ([#571](https://github.com/cuenv/cuenv/issues/571), [#574](https://github.com/cuenv/cuenv/pull/574)). For an AWS SSM parameter:

```cue
configuration: {
    value: schema.#WriteOnly & schema.#OnePasswordRef & {
        ref: "op://Infrastructure/Cloudflare root/credential"
    }
    value_wo_version: 1
}
```

- Verified bindings keep the logical `value` or `password` property and send its resolved value through the provider's write-only argument. Bindings cover AWS SSM parameters, AWS database instances and Azure Key Vault secrets. Other standalone write-only string arguments retain their provider name.
- Write-only attributes stay null in proposed, planned and returned state. A provider that returns a non-null or unknown write-only value is rejected before state or recovery writes.
- Plans show `(write-only)`. Provider diagnostics and logs redact the resolved value, including short and escaped strings.
- Destroy, import and state commands never resolve resource argument secrets.

**Bump the provider's companion version field to rotate a write-only value.** Changing the secret alone does not plan an update. Write-only support is limited to managed string arguments outside sets.

## Upgrade existing provider pins

Upgrade cuenv before using `#WriteOnly`. Providers exposing managed write-only attributes now include a generation-contract marker in their schema digest. Re-add an affected provider at its currently pinned version with `cuenv infrastructure provider add <source>@<same-version>`; this updates its pin and generated types. Sync and init verify the existing pin and cannot repair an older digest.

Providers remain trusted programs: opaque private bytes and unrelated state fields remain provider-owned.
