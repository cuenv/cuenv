# cuenv 0.68.0

## Infrastructure: secrets in resource arguments

A string argument of a resource or data source can now be a `#Secret`
([#570](https://github.com/cuenv/cuenv/issues/570)). This covers the case a provider
environment variable cannot: copying a credential from one secret manager into another,
or giving a resource a token it must store.

```cue
let cloudflareRoot = schema.#OnePasswordRef & {ref: "op://Infrastructure/Cloudflare root/credential"}

infrastructure: resources: ci_cloudflare_token: infisical_secret.#Resource & {
	configuration: {
		name:  "CLOUDFLARE_API_TOKEN"
		value: cloudflareRoot
		// ...
	}
}
```

- The secret is resolved with the project's own resolvers, only when the configuration
  reaches a provider, and once per command however many arguments name it. CUE never
  sees the value. `destroy`, `import` and the state commands never resolve it.
- Plans show the argument as `(sensitive)`, a rotated secret plans an update without
  printing either value, and the value is registered for redaction before any provider
  receives it.
- A secret that cannot be resolved fails with exit code 3 and names the resource, the
  argument and the resolver, never the resolver's own output.
- Generated resource and data source types accept `string | #Secret` at every string
  position outside sets. Run `cuenv sync infrastructure` to regenerate them.

**The value is stored in state.** Providers return the arguments they receive, so the
resolved value is written to the resource's state record in plaintext, marked sensitive,
as Terraform does. Treat access to the state backend as access to the secret. Write-only
arguments, which keep a secret out of state, are
[#571](https://github.com/cuenv/cuenv/issues/571).

A secret cannot go in a number, a bool, a set element, a computed-only or write-only
argument, or a provider's `configuration` yet. The decision is recorded in
[ADR-0013](../src/content/docs/decisions/adrs/adr-0013-secrets-in-infrastructure-arguments.md).

## Nix package

`packages.<system>.cuenv` is now the Nix-native package, the same as `default`, with its
runtime dependencies. The `cuenv-nix` alias is gone: a NixOS, nix-darwin or home-manager
configuration that named it should use `cuenv` or `default`. Portable release binaries
are built separately, and the Linux ones still target glibc 2.17.
