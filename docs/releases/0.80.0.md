# cuenv 0.80.0

## Upgrade notes

This release changes how infrastructure output references are written. It is breaking: a configuration that reads an output must be updated before it plans again. The change makes every infrastructure configuration evaluate with plain `cue export` and `cue eval`, which the previous abstract `outputs` declarations did not.

- **Untyped outputs are declared by type.** Write `outputs: id: type: "string"` instead of `outputs: id: string`. The types are `"string"`, `"number"`, `"bool"`, `"list"` and `"object"`. Each `outputs` field now exports as a concrete reference descriptor. Regenerate provider types with `cuenv sync infrastructure` (or `cuenv infra init`): generated `#Outputs` changed shape.
- **Interpolation, arithmetic and builtins can no longer read an output.** A reference is a struct, so `"app-\(ref)"` and `ref + 1` fail in CUE. Use the new schema functions:
  - `"app-\(ref)"` becomes `schema.#Format & {parts: ["app-", ref]}`.
  - `strings.Join([a, ref], ",")` becomes `schema.#Join & {items: [a, ref], separator: ","}`.
  - `hex.Encode(sha256.Sum256(ref))` becomes `schema.#Sha256 & {of: ref}`; add `encoding: "base64"` for base64.
  - `base64.Encode(null, ref)` becomes `schema.#Base64 & {of: ref}`; add `encoding: "url"` for the URL-safe alphabet.
  - There is no replacement for arithmetic, `json.Marshal` or a constraint over an output such as `ref & =~"^prod-"`.
- **List and object outputs are read with `#Select`.** `outputs.result[0].id` becomes `schema.#Select & {from: infrastructure.data.groups.outputs.result, path: [0, "id"], type: "string"}`. Untyped lists are declared `outputs: result: type: "list"` instead of `[{id: string}]` or `[_]`.
- **Resources declared inside your own definitions must be typed.** A resource in a closed user definition needs `schema.#ManagedResource` or a generated `#Resource`, and a separate infrastructure package needs `schema.#Infrastructure & {...}`; otherwise CUE refuses the descriptor fields.
- **A CUE default no longer waits for an output.** `*"fallback" | ref` evaluates to `"fallback"`.
- **Every environment must be concrete for `plan`, `apply` and `destroy`,** including environments not selected with `--env`. An environment that does not export with `cue export` is refused.
- **Declared outputs that nothing reads are no longer checked against the provider schema.** Referenced outputs still are.
- **`cuenv sync -A` now finds `.rules.cue` files.** Repos with `.rules.cue` in several directories get one merged `CODEOWNERS`. Skip a subtree with the new `exclude: [...]` field of `#DirectoryRules` ([#687](https://github.com/cuenv/cuenv/pull/687)).
- **The CUE bridge exports numbers exactly.** Numbers keep their source text instead of passing through a 64-bit float. A number in the selected infrastructure configuration that cannot be represented without rounding is refused before any provider call.

## Features

- **Concrete infrastructure output references.** Configurations that read outputs now pass `cue export` and `cue eval` unchanged; the export shows each reference as `{"cuenvOutput": {...}, "type": "string"}`. cuenv fills in real values in Rust at plan and apply time, instead of evaluating CUE again with real outputs. A reference must name a declared output of the same environment and match the receiving argument's type. A string computed from a secret is registered for redaction ([#690](https://github.com/cuenv/cuenv/pull/690), [#521](https://github.com/cuenv/cuenv/issues/521)).
- **Inline tasks in CI pipelines.** A `schema.#Task & {...}` entry in `ci.pipelines.<name>.tasks` compiles and runs. It is named by its `description`, exists only in that pipeline (`cuenv task` does not list it), and `cuenv ci --all` runs it. A name that clashes with a project task or another inline task in the pipeline is an error. See `examples/ci-inline-task` ([#698](https://github.com/cuenv/cuenv/pull/698), [#696](https://github.com/cuenv/cuenv/issues/696)).
- **Progress while runtimes activate.** Nix and devenv activation, the one-time devenv install and `#ToolsRuntime` downloads show a spinner on a terminal and plain progress lines elsewhere, once the work outlasts 200 ms. Task stdout is untouched ([#689](https://github.com/cuenv/cuenv/pull/689)).

## Fixes

- **A task can use `if` or `for`.** The command-or-script rule of `#Task` was a disjunction, which CUE cannot resolve next to a pending comprehension, so plain `cue export` failed. Setting both `command` and `script` is still an error. A task with neither now passes `cue export` and is refused when cuenv loads it ([#694](https://github.com/cuenv/cuenv/pull/694), [#693](https://github.com/cuenv/cuenv/issues/693)).
- **A sequence can hold or alias another sequence.** The project no longer evaluates to null ([#697](https://github.com/cuenv/cuenv/pull/697), [#692](https://github.com/cuenv/cuenv/issues/692)).
- **Colour is forced into task children only when cuenv's output is a terminal**, and never with `NO_COLOR` set. Values set by the task or caller are kept ([#695](https://github.com/cuenv/cuenv/pull/695)).
- **Gitignored directories are left out of module evaluation**, and CUE modules are tested on v0.18.0 ([#688](https://github.com/cuenv/cuenv/pull/688), [#686](https://github.com/cuenv/cuenv/issues/686), [#555](https://github.com/cuenv/cuenv/issues/555)).
- **Stored sensitive objects no longer register their schema labels as secrets**, so fixed labels such as `name` and `token` are not redacted for the rest of a run ([#687](https://github.com/cuenv/cuenv/pull/687), [#678](https://github.com/cuenv/cuenv/issues/678)).
- **Task references resolve through `let` bindings, label aliases and hidden fields**, not only `_t` and `_tasks` ([#687](https://github.com/cuenv/cuenv/pull/687), [#685](https://github.com/cuenv/cuenv/issues/685)).
