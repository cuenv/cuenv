# cuenv 0.80.0

## Upgrade notes

This release changes how infrastructure output references are written. It is breaking: a configuration that reads an output must be updated before it plans again. The change makes every infrastructure configuration evaluate with plain `cue export` and `cue eval`, which the previous abstract `outputs` declarations did not.

- **Untyped outputs are declared by type.** Write `outputs: id: type: "string"` instead of `outputs: id: string`. The types are `"string"`, `"number"`, `"bool"`, `"list"` and `"object"`. Each `outputs` field now exports as a concrete reference descriptor. Regenerate provider types with `cuenv sync infrastructure` (or `cuenv infra init`): generated `#Outputs` changed shape.
- **Interpolation, arithmetic and builtins can no longer read an output.** A reference is a struct, so `"app-\(ref)"` and `ref + 1` fail in CUE. Use the new schema functions:
  - `"app-\(ref)"` becomes `schema.#Format & {parts: ["app-", ref]}`.
  - `strings.Join([a, ref], ",")` becomes `schema.#Join & {items: [a, ref], separator: ","}`.
  - `hex.Encode(sha256.Sum256(ref))` becomes `schema.#Sha256 & {of: ref}`; add `encoding: "base64"` for base64.
  - `base64.Encode(null, ref)` becomes `schema.#Base64 & {of: ref}`; add `encoding: "url"` for the URL-safe alphabet.
  - There is no replacement for arithmetic, `json.Marshal` or a constraint over an output such as `ref & =~"^prod-"`.
- **List and object outputs are read with `#Select`.** `outputs.result[0].id` becomes `schema.#Select & {from: infrastructure.data.groups.outputs.result, path: [0, "id"], type: "string"}`. Untyped lists are declared `outputs: result: type: "list"` instead of `[{id: string}]` or `[_]`.
- **Resources declared inside your own definitions must be typed.** A resource in a closed user definition needs `schema.#ManagedResource` or a generated `#Resource`, and a separate infrastructure package needs `schema.#Infrastructure & {...}`; otherwise CUE refuses the descriptor fields.
- **A CUE default no longer waits for an output.** `*"fallback" | ref` evaluates to `"fallback"`.
- **Every environment must be concrete for `plan`, `apply` and `destroy`,** including environments not selected with `--env`. An environment that does not export with `cue export` is refused.
- **Declared outputs that nothing reads are no longer checked against the provider schema.** Referenced outputs still are.
- **The CUE bridge exports numbers exactly.** Numbers keep their source text instead of passing through a 64-bit float. A number in the selected infrastructure configuration that cannot be represented without rounding is refused before any provider call.

## Features

- **Concrete infrastructure output references.** Configurations that read outputs now pass `cue export` and `cue eval` unchanged; the export shows each reference as `{"cuenvOutput": {...}, "type": "string"}`. cuenv fills in real values in Rust at plan and apply time, instead of evaluating CUE again with real outputs. A reference must name a declared output of the same environment and match the receiving argument's type. A string computed from a secret is registered for redaction.
