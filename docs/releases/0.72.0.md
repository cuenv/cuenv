# cuenv 0.72.0

## Named contexts

A context is a filter over one invocation. While it matches, `env.context.<name>` sets its variables, so two invocations can receive different values for the same variable ([#602](https://github.com/cuenv/cuenv/pull/602)). `cuenv infrastructure plan` can take a read-only token and `apply` the read-write one, both under one name.

- `schema.#When` matches the facts of an invocation (`consumer`, `exec`, `infrastructure`, `ci`, `user`, `host`, `vcs`). `schema.#TaskFilter` matches each task cuenv runs by `name`, `command` and `labels`.
- A filter is plain data that `cue export` accepts. A string is a regular expression that must match the whole value.
- Two contexts that set the same variable must be exclusive, and cuenv proves it from the filters: `"release-1"` and `"release-2"` are exclusive, `"a.*"` and `".*b"` are not.
- `cuenv task` and `cuenv ci` decide contexts for each task of the graph. `cuenv export` and shell hooks select the contexts active for the shell. Services (`cuenv up`) do not read `env.context` yet.
- S3 infrastructure state takes credentials by context through `infrastructure.state.s3.context.<name>`.

Facts are reported by the machine running cuenv. A context chooses what a run asks for; the secrets backend must still enforce who is entitled to it. See the [contexts guide](../src/content/docs/how-to/contexts.md).

## cuenv no longer runs `git`

cuenv reads and fetches repositories in process and does not run `git`, `gh` or `hostname` ([#602](https://github.com/cuenv/cuenv/pull/602)). HTTPS remotes are fetched in process, SSH remotes go through `ssh`, and an on-disk remote through `git upload-pack`.

`subdir` and `overlay` VCS dependencies download only the files under `subdir` when the remote supports partial fetches, and fetch one whole commit otherwise. Vendored files are written through the checkout filters of their own tree (line endings, Git LFS), and `cuenv sync vcs --check` undoes them before comparing.

## Infrastructure

- **Reviewed plans.** `plan` prints a digest of every change to real infrastructure, and `apply --expect-plan <digest>` refuses a plan that differs from the one reviewed. Generated workflows can require it with `apply.requireReviewedPlan`, and the pull request plan job runs with a read-only token ([#587](https://github.com/cuenv/cuenv/pull/587)).
- **Provider signatures.** Every provider download is checked against the release's signed `SHA256SUMS`. A provider can pin `signingKeys`; a pinned provider's cache is reused only when its kept archive still matches `cuenv.lock`.
- **Resource identity.** cuenv stores the identity providers return and sends it back on refresh, plan and apply, so importing from providers that declare identity (AWS 6.x, for example) works.
- **In-flight markers.** Before each provider change cuenv records a marker in the shared backend. Plans, applies and imports refuse while one exists, so a change whose outcome was lost is not repeated by another runner.

## Fixes

From the audit in [#603](https://github.com/cuenv/cuenv/pull/603):

- A cycle in the task graph failed `cuenv task` and `cuenv ci` silently: they reported success with nothing run. They now fail.
- `GITHUB_ACTIONS=false` no longer auto-approves hooks.
- When affected-task detection cannot build its index, CI runs every pipeline task instead of none. Push events read `before` from the event payload, so multi-commit pushes select every affected task.
- GitHub releases are looked up by the configured tag prefix, which is empty by default.
- `cuenv sync lock --dry-run` and `cuenv task -i --dry-run` no longer make changes. `cuenv env list` accepts the default `text` format.
- `watch.on: "sync"` no longer starts a second copy of a service. An `https://` readiness probe is rejected, because the probe speaks plaintext.
- Extracting a tool archive whose only entry is a symbolic link no longer moves the link's target into the tool cache.

## Cuetty

The terminal keeps the window's full width. Tabs float over its right edge and the project panel opens from a pill at the top right; pin it with its button or Cmd/Ctrl-Shift-B. `sidebar` takes `"floating"` (default) or `"pinned"`.

## Breaking changes

- `cuenv release prepare` commits to the release branch and stops. It no longer pushes the branch or opens a pull request. `--no-pr` is accepted and ignored, with a warning.
- The `task` fact of the earlier, unreleased context design is replaced by `#TaskFilter`, and the `command` fact is `consumer`.
- `allowTasks` is checked for each task that runs, not for the task that was asked for. A variable allowed only for `deploy` no longer reaches `deploy`'s dependencies, and one allowed for `build` reaches `build` when it runs as a dependency. A group or sequence name covers the tasks under it.
- Affected detection reports a renamed file under both its old and new path.
- For a `subdir` or `overlay` dependency, `.gitattributes` above `subdir` no longer apply.
- Bitbucket `CODEOWNERS` is generated at `.bitbucket/CODEOWNERS`. Remove the root `CODEOWNERS` an earlier cuenv generated; nothing removes it for you.

This release includes all changes from [0.71.0](0.71.0.md).
