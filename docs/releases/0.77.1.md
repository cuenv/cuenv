# cuenv 0.77.1

## Remote caching and Linux strict sandboxing fixes

- **Linux strict sandbox `chroot` fallback under container seccomp**: When `SYS_pivot_root` is blocked by a container seccomp filter (`EPERM`/`ENOSYS`, such as on Namespace Linux runners) or `/` is a non-pivotable initramfs (`EINVAL`), `enter_linux_sandbox` now falls back to plain `chroot(new_root)` + `chdir("/")` (without `MS_MOVE`, preserving Linux's `current_chrooted()` protection against nested `CLONE_NEWUSER` while dropping all setup capabilities) so verified Nix closure and runtime-image tasks stay publish-eligible with identical action keys ([#646](https://github.com/cuenv/cuenv/pull/646)).
- **Bazel credential helper URI normalization**: `invoke_credential_helper` now normalizes `grpcs://` to `https://` and `grpc://` to `http://` before passing `{"uri": ...}` to Bazel credential helpers, matching Bazel's convention so `bazel-credential-nsc` works directly with `/etc/bazel.bazelrc` `grpcs://` endpoints ([#646](https://github.com/cuenv/cuenv/pull/646)).
- **Dynamic trigger gating for `cache.remote.ci.authMode: "ambient"`**: `cuenv sync ci` now emits dynamic GitHub Actions expressions for `CUENV_REMOTE_CACHE_UPLOAD` and `CUENV_CACHE_DIR` when an `ambient` workflow combines protected push/tag/release triggers with `manual: true` (`workflow_dispatch`) or `scheduled` triggers (without `pullRequest: true`), allowing protected runs to upload while keeping manual and scheduled runs read-only ([#646](https://github.com/cuenv/cuenv/pull/646)).
