# cuenv 0.67.0

## Infrastructure: output references come from the evaluator

0.65.0 failed in both directions, because the bridge rebuilt from source text what
the CUE evaluator already knows. Any comprehension in a package failed with `the
frozen CUE infrastructure could not be inspected`
([#566](https://github.com/cuenv/cuenv/issues/566)), and a conditional inside an
imported definition could read an output with no dependency recorded, so a consumer
was applied before its producer. Both are fixed
([#567](https://github.com/cuenv/cuenv/pull/567)): dependencies now come from what
the evaluator bound, through `cue/provenance` in the pinned CUE fork.

- A scalar argument can read an output however CUE lets you write it, and can be
  computed from several with interpolation, arithmetic or builtins. It stays unknown
  until they are all known.
- Conditions, labels, indexes and defaults that read an output are refused before
  any provider change.
- A check the configuration does not read is no longer refused at plan. It is verified
  when the real value exists, so a violation stops the apply after earlier resources
  have changed.
- Every declared output is checked against the provider's schema while planning.
- Analysis costs what the configuration reaches, not what the project holds.

Two ways a provider could receive a wrong value are gone. A conflict inside a `let` or
an inline value was lost when an expression read it, and a snapshot read `@embed` files
from disk each time it was evaluated, so an edit between plan and apply changed what was
applied.

The Turso store now retries `SQLITE_BUSY` for thirty seconds rather than giving up after
about 1.4 seconds, which could stop an apply with an unrecorded change.

### Known limits

- A self-hosted `sqld` 0.24.32 can stop serving writes under concurrent writers, until it
  is restarted. A run stops with a timeout, and with an unrecorded change if it had
  changed a resource. See the
  [design notes](../design/specs/2026-11-03-infrastructure-nested-output-references.md).
- Analysis has not been measured against a provider as large as Cloudflare.

## Breaking changes

Dagger support and code nothing calls are removed
([#568](https://github.com/cuenv/cuenv/pull/568)).

- Configurations using `#DaggerRuntime`, `dagger:`, `config: backend:` or a missing
  imported definition now fail evaluation.
- `cuenv task --backend`, `--materialize-outputs` and `--show-cache-path`, `cuenv ci
  --filter-matrix` and `cuenv web` are gone.
- `cuenv exec` exits with the child's status, or 128 plus the killing signal, and no
  longer with `2`.
- Action keys no longer record a backend, so existing cache entries miss once.

`cuenv sync rules` and `cuenv sync git-hooks` now exist.

## Cuetty

The experimental Cuetty terminal has a sidebar of named tabs with their directory, branch
and activity, a search bar with highlighted matches, whole-palette themes that can follow
the desktop's light or dark, and a task palette. Box and block characters are drawn on the
cell grid. It is a separate application and is not included in the cuenv CLI release
binaries.
