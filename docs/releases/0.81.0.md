# cuenv 0.81.0

## Upgrade notes

This release is additive. Every new field is optional, so existing configurations evaluate and generate the same workflows as before. Run `cuenv sync ci` after you adopt a new field to regenerate the workflows.

## Features

GitHub Actions workflow generation now covers what a hand-written workflow needs. Every new field evaluates with plain `cue export`.

- **Triggers.** `when.mergeGroup` emits `on.merge_group`, with a concurrency group that never cancels queue entries. `when.workflowRun` emits `on.workflow_run` (`workflows`, `types`, `branches`). `when.pullRequest` accepts a struct with `types`, `branches`, `paths` and `pathsIgnore`. Derived path filters are not added to `merge_group` or `workflow_run` ([#718](https://github.com/cuenv/cuenv/pull/718), [#630](https://github.com/cuenv/cuenv/issues/630), [#700](https://github.com/cuenv/cuenv/issues/700), [#701](https://github.com/cuenv/cuenv/issues/701)).
- **Permissions, run name and concurrency.** `#GitHubPermissions` covers all 16 token scopes. An explicit empty `permissions: {}` is kept and fails `cuenv sync ci` if a task or emitted step needs a scope you withheld. `runName` sets `run-name`. Pipelines take `concurrency` as a boolean, an expression or a per-event map ([#717](https://github.com/cuenv/cuenv/pull/717), [#629](https://github.com/cuenv/cuenv/issues/629), [#702](https://github.com/cuenv/cuenv/issues/702), [#703](https://github.com/cuenv/cuenv/issues/703), [#704](https://github.com/cuenv/cuenv/issues/704)).
- **Job settings.** Per task: `runner` (a label, a list or an expression), `timeoutMinutes`, `environment`, `container`, `defaults.run` and `if`. Pipelines take `limits` (`[label]: cap`), which becomes round-robin concurrency slots, and a job `concurrency` group, namespaced by workflow when you set none ([#719](https://github.com/cuenv/cuenv/pull/719), [#723](https://github.com/cuenv/cuenv/pull/723), [#631](https://github.com/cuenv/cuenv/issues/631), [#632](https://github.com/cuenv/cuenv/issues/632), [#706](https://github.com/cuenv/cuenv/issues/706)-[#710](https://github.com/cuenv/cuenv/issues/710)).
- **Pinned actions, checkout options and custom steps.** `ci.github.pins` pins any emitted `uses:` to a 40-character commit SHA, and `requirePinnedActions` refuses anything unpinned. `checkout` sets `fetchDepth`, `submodules`, `ref`, `persistCredentials` and `token` per pipeline or per task. `steps.before` and `steps.after` add `uses` or `run` steps around a task ([#720](https://github.com/cuenv/cuenv/pull/720), [#713](https://github.com/cuenv/cuenv/issues/713), [#714](https://github.com/cuenv/cuenv/issues/714), [#715](https://github.com/cuenv/cuenv/issues/715)).
- **Job outputs and dynamic matrices.** A task declares `outputs` and an optional `stepId`. `#GitHubJobOutput` gives a plain-CUE reference to another job's output, and generation checks that every `needs.<job>.outputs.<name>` it finds targets a declared output of an upstream job. `matrix` takes a list or an expression, wrapped in `fromJSON`, with `failFast` and `maxParallel` ([#721](https://github.com/cuenv/cuenv/pull/721), [#705](https://github.com/cuenv/cuenv/issues/705), [#711](https://github.com/cuenv/cuenv/issues/711)).
- **A gate job.** `gate` emits one stable required check that needs every other job, fails on a failed or cancelled one, and counts a skipped one as passed unless it is in `gate.required` ([#722](https://github.com/cuenv/cuenv/pull/722), [#712](https://github.com/cuenv/cuenv/issues/712)).
- **Per-lane change detection.** `changes` names lanes of task names. A detection job sets up cuenv, reads the tasks the run selected and exposes one output per lane. A lane's jobs wait for it and run only when their lane changed. `changes.script` replaces the default step. Generation rejects unknown lane tasks, invalid lane names, unknown `gate.required` jobs and job ID collisions ([#722](https://github.com/cuenv/cuenv/pull/722), [#724](https://github.com/cuenv/cuenv/pull/724), [#716](https://github.com/cuenv/cuenv/issues/716)).
- **`cuenv ci --dry-run --plan-format lines|json [--output FILE]`** writes the tasks a run would select instead of running them. See `examples/ci-github-generator` for most of the above in one project ([#724](https://github.com/cuenv/cuenv/pull/724)).

## Fixes

- **A change-detection lane no longer captures sibling tasks.** A lane listing `check` used to attach to jobs of `check-lint` and any other task whose ID starts with `check-` ([#723](https://github.com/cuenv/cuenv/pull/723)).
