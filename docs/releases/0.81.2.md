# cuenv 0.81.2

## Fixes

- `cuenv sync` now locks Nix runtimes whose `flake.lock` has relative path inputs such as `path:../../flakes/bun` ([#733](https://github.com/cuenv/cuenv/pull/733)). Nix records these without a `narHash` because the parent flake pins them, and cuenv previously rejected them as unlocked. Absolute path inputs without a hash are still rejected.
- The runtime digest now covers the files under each relative path input, so editing a shared flake makes `cuenv sync --check` report drift instead of leaving a stale digest ([#734](https://github.com/cuenv/cuenv/pull/734)). `lockfile` entries in `cuenv.lock` are stored as normalized module-relative paths, for example `flakes/bun/flake.lock`. Run `cuenv sync` once after upgrading to refresh existing entries.
- Generated provider types in `cue.mod/gen` are regenerated automatically when they are missing or stale, so a fresh clone or a cuenv upgrade no longer fails evaluation until `cuenv sync infrastructure` is run by hand ([#732](https://github.com/cuenv/cuenv/pull/732)).
