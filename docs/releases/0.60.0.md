# cuenv 0.60.0

## Infrastructure: plan and apply from CI

`infrastructure.workflows` makes `cuenv sync ci` write two workflows for the
project's `ci.providers` (GitHub Actions so far):

```cue
ci: providers: ["github"]

infrastructure: workflows: {}
```

- `<project>-infrastructure-plan.yml` runs `cuenv infrastructure plan` on pull
  requests that touch the project, adds the plan to the job summary and keeps
  one pull request comment per project up to date. Set `plan: comment: false`
  to keep only the summary.
- `<project>-infrastructure-apply.yml` runs `cuenv infrastructure apply --yes`
  on pushes to `main`. `apply: on` also takes `"tag"`, `"release"` or
  `"manual"`; `apply: environment` names a GitHub environment for the job.
  Every apply waits for the one in progress instead of cancelling it.

Both reuse the project's `ci` contributors, so cuenv is installed and secret
providers are set up as for its pipelines. They run when any file the CUE
loader builds the project from changes: its own files, same-package files of
parent directories, and every package it imports from the module. Only the
top-level configuration is planned and applied. See
[PR #525](https://github.com/cuenv/cuenv/pull/525) and
[Infrastructure](../src/content/docs/how-to/infrastructure.md#plan-and-apply-from-github-actions).

## Changes to CI generation

- A pipeline's `when.tag` now becomes a GitHub `push.tags` trigger. It was
  dropped before, so pipelines that set it start running on tag pushes.
- Secret-provider contributors (`when: secretsProvider`, such as 1Password)
  now activate from a project's base variables when the pipeline names no
  `environment`, and from secrets inside `infrastructure`. Pipelines without
  an environment that read 1Password references gain the setup step.

## Sync

`cuenv sync` writes the generated infrastructure provider types in
`cue.mod/gen` before any other provider evaluates projects, so a fresh
checkout no longer skips projects that import them.
