# 0.70.0 binary publication recovery

The generated release workflow exported `CUENV_ARCH` as the literal passthrough
marker instead of the matrix architecture. The binary build refused that value
before compilation. CUE publication and the documentation jobs succeeded separately.

This temporary recovery branch supplies each architecture explicitly, checks out
the existing annotated `0.70.0` tag, and verifies commit
`c02cd755b4cbc3257a5b7a44121bb27e25b179cb` in every job. GitHub asset publication and
Homebrew target `0.70.0`; CUE and documentation publication are skipped to avoid
repeating completed work. The product source and release tag remain unchanged.

Each task runner realizes and uses the Nix CLI from that verified checkout,
checking its version before execution. This avoids comparing a copied bootstrap
executable with a different runner's Nix store output while retaining the local
runtime closure.

Dispatch the existing `cuenv-release.yml` workflow from this branch with
`tag_name=0.70.0`. This is an operational recovery, not the permanent workflow
generator correction.

The final publication-only workflow downloads all three verified binary artifacts
from run [42313030213](https://github.com/cuenv/cuenv/actions/runs/42313030213).
It runs the existing upload and Homebrew tasks against the unchanged tag without
rebuilding binaries. Release context is set in the shell command because GitHub's
runner restores its reserved `GITHUB_*` variables after applying step environment
entries. Cross-run artifact access grants `actions: read` only to the upload job.
