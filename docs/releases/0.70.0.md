# cuenv 0.70.0

## Native Terraform write-only arguments

Infrastructure configuration now preserves Terraform provider attribute names and uses the live schema's `write_only` flag ([#578](https://github.com/cuenv/cuenv/pull/578)). Ordinary `value` and write-only `value_wo` remain separate arguments; provider validation owns any conflict between them. There is no provider allowlist or argument remapping.

```cue
configuration: {
    value_wo: schema.#WriteOnly & schema.#OnePasswordRef & {
        ref: "op://Infrastructure/Cloudflare root/credential"
    }
    value_wo_version: 1
}
```

- Marking an ordinary argument with `#WriteOnly` fails before secret resolution.
- Optional write-only nulls are treated as absence. Supplied write-only values still require a secret descriptor.
- Write-only state remains null, plans stay value-free, and companion versions remain manual.

**Migrating from 0.69.0:** replace logical aliases with native provider names, such as `value_wo` or `password_wo`. After upgrading cuenv, refresh affected provider pins with `cuenv infrastructure provider add <source>@<same-version>`. Write-only schema digests now use contract 2; no state or lockfile format migration is needed.

## Faster CI

CI avoids repeated cuenv bootstrap builds and reuses runner-specific binaries across orchestrated jobs ([#575](https://github.com/cuenv/cuenv/pull/575)). Nix dependency preparation matches each check's scope and profile, Cuetty tests compile directly in the test profile, and checks retain their validation coverage. The unused FlakeHub input is removed; Namespace Nix caching and upstream Nix installation are configured explicitly.
