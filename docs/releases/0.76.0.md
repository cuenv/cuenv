# cuenv 0.76.0

## Project discovery walks what CUE loads

Every walk for `env.cue` files in a module now visits the directories CUE's
`./...` pattern loads ([#622](https://github.com/cuenv/cuenv/pull/622)). This
covers `cuenv ci`, `cuenv info`, completions, and the per-directory fallback of
`cuenv task` and `cuenv sync`. An `env.cue` in any of these directories is no
longer a project of the module:

- the module's `cue.mod` directory, including packages vendored under
  `cue.mod/pkg`, which `cuenv ci` tried to evaluate and failed on;
- a nested CUE module, meaning any directory with its own `cue.mod`;
- `testdata` directories;
- directories whose name starts with `.` or `_`.

**Breaking:** a project in a directory named like `_internal` or `.config` is
no longer discovered, as CUE would not load it either. Rename the directory, or
run cuenv inside a nested module to work with its projects. To use the values of
a vendored package, import it.

## Matrix entries over a task reached through a `let`

The CUE bridge pins the fork at
[`badfad1`](https://github.com/rawkode/cue/commit/badfad1109de70ce104a0637d9d853cf7ead536d)
([#623](https://github.com/cuenv/cuenv/pull/623)). Each of these used to run out
of memory as soon as the task had a dependency:

- a matrix entry over a task reached through a `let`:
  `let _tasks = tasks` with `task: _tasks.build`;
- a task typed `schema.#TaskNode & {...}`.

Both now evaluate in well under a second. The bridge reads every field's
references through `Value.Expr`. For a field that CUE first added in a disjunct
it later superseded, `Value.Expr` evaluated the field's operands in that
abandoned disjunct, which repeated work for every task the dependencies reach.
The fork evaluates the operands where the value settled.

This fix needs no configuration change.
