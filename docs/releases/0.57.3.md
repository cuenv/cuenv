# cuenv 0.57.3

Evaluating projects with `dependsOn` chains is no longer exponential in chain
depth. `dependsOn` entries on tasks, task groups, container images and services
were typed as `#TaskNode` unions; CUE stops sharing a reference once it is
unified with a definition, so every referenced task, including its own
`dependsOn`, was re-evaluated once per reference path. A chain of plain tasks
only two edges deep could exceed the default 60-second evaluation timeout. A
twenty-edge chain now evaluates and runs in about a second.

The entries are now untyped references. Strings (`dependsOn: ["build"]`) and
output references (`build.stdout`, `images.base.ref`) are still rejected during
evaluation with a `dependsOn[N]` error, and every example project exports
identical JSON. See [Dependency references](../src/content/docs/reference/cue-schema.md#dependency-references).

Known limit: export still writes each dependency's full value, so projects with
heavy fan-in (many tasks sharing the same dependencies over many layers) remain
slower than they should be. That is tracked as a follow-up in the Go bridge.

This release includes [PR #515](https://github.com/cuenv/cuenv/pull/515).
