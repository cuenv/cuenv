# cuenv 0.57.3

cuenv now builds against the patched [CUE fork at `4cee740`](https://github.com/rawkode/cue/commit/4cee740431d059398b71ce4c22906300c196b212),
based on CUE 0.16.1, using Go 1.26.
The fork backports the [recursive-definition sharing fix](https://github.com/rawkode/cue/commit/304ad24c7bcc1d48fa47c2e65e98cb25d21955e0)
from CUE master. It preserves structure sharing when a reference is unified with
a recursive definition. Previously, typed `dependsOn` graphs could re-evaluate a
dependency once per path, making evaluation grow exponentially.

This release also retains [PR #515](https://github.com/cuenv/cuenv/pull/515)'s
schema workaround: dependency entries remain untyped references. Strings
(`dependsOn: ["build"]`) and output references (`build.stdout`, `images.base.ref`)
are still rejected during evaluation. Full-schema benchmarks still time out
with typed entries, so they have not been restored. See the
[evaluation measurements](../design/specs/cue-recursive-sharing.md) and
[Dependency references](../src/content/docs/reference/cue-schema.md#dependency-references).

Regression tests cover task, task group, container image and service dependency
chains, plus a small diamond graph and decoded dependency names.

The repository root and all 34 example projects export identical JSON to CUE
0.16.1, including source metadata and dependency references.

Known limit: export still writes each dependency's full value, so projects with
heavy fan-in (many tasks sharing the same dependencies over many layers) remain
slower than they should be. That is a separate follow-up in the Go bridge.
