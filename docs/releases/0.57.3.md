# cuenv 0.57.3

cuenv now builds against the patched [CUE fork at `183f265`](https://github.com/rawkode/cue/commit/183f265db67b96a257846cc77c9db23bd6a95ca1),
based on CUE 0.16.1, using Go 1.26.

The fork makes structure sharing independent of declaration order. CUE 0.16.1
only shares a reference into a closed definition when the referenced field has
already been marked closed. A field that had not been evaluated yet was copied
instead, together with every reference inside it. A project that declares
`ci: pipelines` before `tasks`, or a task that depends on a task declared later,
therefore re-evaluated whole dependency closures at each reference. The fork
treats an unevaluated field whose parent is closed as closed, which is the flag
that evaluation would set. The fork also carries the
[recursive-definition sharing backport](https://github.com/rawkode/cue/commit/4cee740431d059398b71ce4c22906300c196b212).

Pipeline `tasks` entries, `#MatrixTask.task` and service `watch.rebuild`
entries are now untyped references, like `dependsOn` since
[PR #515](https://github.com/cuenv/cuenv/pull/515). Typing them as
`#PipelineTask` or `#TaskNode` re-evaluated the referenced task and its
dependency closure at every entry. Strings, other scalars and output references
are still rejected. Matrix entries are still validated against `#MatrixTask`,
whether or not they spell out `type: "matrix"`. Entries that omit it now export
without `type` and without an empty `matrix`; cuenv reads them as before, and
`cuenv sync ci` output is unchanged.

Measured on the waddle-social/waddle repository, `cuenv task` for the slowest
`env.cue` (`chat`) dropped from 1.2 s to 0.2 s, and every project evaluates in
under half a second. See the
[evaluation measurements](../design/specs/cue-recursive-sharing.md) and
[Dependency references](../src/content/docs/reference/cue-schema.md#dependency-references).

Projects must use the 0.57.3 schema to benefit. The 0.57.2 schema's typed
`dependsOn` entries remain exponential on any CUE version.

Regression tests cover task, task group, container image and service dependency
chains, a small diamond graph, pipelines declared before their tasks, and the
pipeline and rebuild rejections.

Known limit: export still writes each dependency's full value, so projects with
heavy fan-in (many tasks sharing the same dependencies over many layers) remain
slower than they should be. That is a separate follow-up in the Go bridge.
