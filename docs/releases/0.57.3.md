# cuenv 0.57.3

cuenv now builds against the [CUE fork at `5a1f958`](https://github.com/rawkode/cue/commit/5a1f958250d657f19d94121d0070ddd1faca6805),
based on CUE 0.16.1, using Go 1.26.

The fork makes typed dependency graphs evaluate in linear time. Stock CUE never
shares a reference unified with a type such as `#TaskNode | #ContainerImage`,
so each referenced task was replayed into every branch of the union, including
the typed references inside it, and evaluation grew exponentially with the
depth of the graph. The fork shares the reference when the referenced task was
declared with one of the type's definitions and the other definitions cannot
be unified with that one. It also shares forward references, so declaration
order no longer matters.

The schema types that
[PR #515](https://github.com/cuenv/cuenv/pull/515) removed are restored:
`dependsOn` on tasks, task groups, container images and services is again
typed with `#TaskNode` unions. Strings and output references fail evaluation at
the entry. Pipeline `tasks`, `#MatrixTask.task` and service `watch.rebuild`
keep their types.

On the waddle-social/waddle repository, which pins the 0.57.2 schema with typed
`dependsOn`, `cuenv task` for `chat` drops from 39 seconds to 0.2 seconds, and
every project evaluates in under 0.4 seconds. Exports are byte-identical to
stock CUE. See the
[evaluation measurements](../design/specs/cue-recursive-sharing.md) and
[Dependency references](../src/content/docs/reference/cue-schema.md#dependency-references).

Regression tests cover task, task group, container image and service dependency
chains, a small diamond graph, pipelines declared before their tasks, and the
dependsOn, pipeline and rebuild rejections.

Known limit: export still writes each dependency's full value, so projects with
heavy fan-in (many tasks sharing the same dependencies over many layers) remain
slower than they should be. That is a separate follow-up in the Go bridge.
