# cuenv 0.57.2

Generated GitHub Actions jobs now receive permissions from their own tasks and
the contributor steps they execute. Expanded lint/test jobs start with only
`contents: read`; thin jobs retain the checks and PR grants used by their reporter.

## Breaking permission configuration change

Global and pipeline `provider.github.permissions` maps are now ceilings. They
limit named scopes and never grant access; omitted scopes remain unrestricted,
and `none` forbids access. Move required grants onto the relevant task or
contributor task with `ci.github.permissions` before regenerating workflows.

Contributor tasks can use `ci.github.tasks` to select the task IDs receiving a
step. Trusted publishing declares OIDC and targets `publish.crates` and
`publish.cue`; override those selectors for custom publishing task names.
Bootstrap jobs ignore pipeline maps and retain their own injected steps' grants.
Determinate/FlakeHub authentication declares OIDC; Hestia GC retains Actions
write access for cache administration. Deployment and Orchestrator-output
inference stays scoped to the executing task.

Run `cuenv sync ci` after upgrading, commit the generated workflows, and verify
with `cuenv sync ci --check`. See the [CI contributor permission reference](../src/content/docs/reference/ci-contributors.md#github-job-permissions)
for the complete semantics and migration examples.
