6. Controlled lock-contention reproducer

  cargo test --manifest-path /workspace/scratch/05001217590d/cuetty-terminal-validation/Cargo.toml --locked --offline diagnostic_bracketed_mode -- --ignored --nocapture --test-threads=1

This scratch-only diagnostic holds the terminal mutex for 100 ms while sending
raw abc through the same Machine input channel. It does not change Rio or the
product source. It intentionally stresses the public shared-state boundary.
Exit 101 on the first raw session. Observed 1 failure in 1 forced-contention run:
  round=0 at=1.441479ms spawn=raw pid=675 fd=3
  at=8.056282ms fixture=raw pid=675 mode=Mode(SHOW_CURSOR | LINE_WRAP | ALTERNATE_SCROLL | URGENCY_HINTS | GRAPHEME_CLUSTER) bytes=[61, 62, 63]
  at=5.006818808s fixture=raw pid=675 done=false io_finished=true effects=[ChildExited(Some(0)), Close]
  missing "M0-BYTES:616263", frame="M0-READY"

This first-session reproducer means previous-session teardown/PID reuse is not
required to trigger the observed final-output loss. It is not yet a statistical
claim of deterministic failure across repeated independent executions.

Source-backed likely cause, not an instrumented branch trace:
Pinned rio-vt/src/performer/mod.rs, pty_read, buffers bytes in local unprocessed.
If try_lock_unfair fails, it continues to read. If the next read returns Linux
EIO after child hangup, the error branch returns before parsing already-buffered
bytes, discarding them. The child-exit branch calls pty_read again but cannot
recover bytes already consumed. The contention probe and zero child exit status
are consistent with this defect. An upstream focused regression test/fix and
requalification remain necessary.
